# Linker (stage 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Link several independently assembled SIC/XE sources into one relocatable program, Beck's linkage editor, and load it at a user-chosen address with a relocating loader. Every stage is visible in the UI.

**Architecture:**
- **Assembler:** each file goes through the macro processor and the assembler, which now returns an `ObjectProgram` (Beck's H/D/R/T/M/E data plus source notes).
- **Linker:** a pure function runs Beck's two passes and returns one linked `ObjectProgram` relative to 0, an ESTAB, a trace and origin ranges.
- **Loader:** a pure function adds PROGADDR to every relocation field.
- **Placement:** all three live in the `sicxe_assembler` static lib.
- **Integration:** `SICXE` wires them behind a new multi-file `IArchitecture::load_files`.
- **Frontend:** the frontend renders the text the backend sends: `.obj`, `.out`, the ESTAB and the trace.

**Tech Stack:**
- **Backend:** C++20, CMake + Ninja, nlohmann/json, cpp-httplib WebSocket.
- **Tests:** the dependency-free test runners (`CHECK`/`TEST`), and Node `node:test` API suites.
- **Frontend:** Next.js 16, React, vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-24-linker-design.md`. Read it before any task; section numbers below (§) refer to it.

## Global Constraints

- **Beck first:** Beck's conventions (*System Software* §2.3.5, §3.2.3, §3.4.1) take priority over the course slides. `ENTRY` is the only addition beyond Beck (§4.2).
- **Variant:** "ligador only", meaning a linkage editor plus a relocating loader. The linker never knows the load address.
- **Directives:** `CSECT`, `EXTDEF`, `EXTREF`, `ENTRY`. They are case-insensitive, like every directive today.
- **External references:** allowed only in format-4 address fields (5 half-bytes) and in `WORD` (6 half-bytes).
- **`END`:** one `END` per file. Its operand resolves in the file's first section, and the transfer address goes on that section's E record.
- **`ENTRY` count:** exactly one `ENTRY` across the link set when it has 2+ files. It is optional with 1 file.
- **Start addresses:** every `START`/`ENTRY` operand must be 0 in a 2+ file link. A single file with `START n≠0` is absolute, and a nonzero load address is then an error.
- **SIC mode:** linking is SIC/XE only. In SIC mode, 2+ files, `CSECT`/`EXTDEF`/`EXTREF`, or a nonzero load address is an error.
- **Errors are never guesses:** every error stops the Run before memory changes.
- **Regression:** the 87 ctest cases and 140 API tests stay green. A single-file load gives byte-identical memory to today.
- **Language:** user-facing labels in PT and EN via `frontend/src/lib/i18n.tsx`.
- **Formatting:** backend code follows the surrounding style (2-space indent in `src/Assembler/*`, 4-space in `SICXE.cpp`/`Server.cpp`).
- **Branch and commits:** work on branch `feat/linker`, cut from the current branch after its pending instruction-table work is committed. Commit once per task, with messages in the repo's style (`[Feat]: …`, `[Test]: …`), ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Commands:**
- **Build:** `cmake --build backend/build`
- **C++ tests:** `ctest --test-dir backend/build --output-on-failure [-R <regex>]`
- **API tests:** `cd backend/tests/api && npm test`
- **Frontend tests:** `cd frontend && npx vitest run [file]`

## Review Focus

1. **`reset` after a relocated load** puts PC at PROGADDR + transfer, not at the bare transfer address. Test in Task 6.
2. **`RESW`/`RESB` at the end of the program, past the end of memory at the chosen load address,** is a fit error, even though those bytes are never written. The fit check uses the section length, not the emitted bytes. Test in Task 5.
3. **A file in the link set that is renamed, moved or deleted** is renamed in or dropped from the set. Run never sends a path that no longer exists. Test in Task 10.
4. **Lowercase `csect`/`extref`/`extdef`/`entry`** work exactly like uppercase. Test in Task 2.
5. **A Run that fails in the linker after a successful Run** shows no stale `.out`, ESTAB or trace from the previous Run. Test in Task 13.
