Session-scoped project storage and architecture info for the SIC-XE Simulator.

HTTP API for the SIC-XE Simulator.

Projects are scoped to an anonymous session. The browser's local storage is the source of truth: the client obtains a session ID (or reuses the one stored in its cookies), bulk-syncs its projects to the server, and then keeps them updated incrementally. The server acts as a persistent mirror/cache of the client's data.

Client flow

  1. If no session ID is stored in cookies, call POST /sessions, then keep the ID in memory and in a cookie (written by the frontend, not the server).
  2. If a session ID is found in cookies, optionally validate it with GET /sessions/{sessionId}.
  3. Call PUT /sessions/{sessionId}/projects to sync all local projects.
  4. Use the per-project and per-file operations for incremental updates.

Session recovery

If any session-scoped call returns 404 with type: session-not-found (for example after a server restart or instance spin-down), the client must request a new session, store it, and repeat step 3. Nothing is lost because browser storage remains the source of truth.

Conventions

  • All bodies are application/json (UTF-8).
  • Project IDs are generated by the client (UUID); session IDs are issued by the server.
  • File paths are relative to the project root, with no leading slash.
  • Errors use an RFC 9457-style problem object (see Error).

Security

No authentication is required at this stage: possession of a session ID grants access to its data. Treat session IDs as secrets. Authentication is planned for a later version.

Sync all projects from the client

Replaces the session's entire project set with the supplied list. Projects missing from the request are deleted on the server; unknown projects are created; existing ones are overwritten. Intended to be called once after the session is established (or re-established), using browser storage as the source of truth. Idempotent.

path Parameters
sessionId
required
string <uuid>

Session ID issued by POST /sessions and stored by the client in its cookies.

required

required
string non-empty

Human-readable project name.

string (Architecture)

required
object

required
string <uuid>
